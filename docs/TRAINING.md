# ทำโมเดลตรวจจับไฟจริง (Training guide)

คู่มือนี้พาจาก **"ยังไม่มีภาพเลย"** ไปจนถึง **"มีโมเดลที่ติดตั้งบนเครื่องแล้วและรู้ว่ามันใช้ได้จริงหรือไม่"**

ต่างจาก [MODEL.md](MODEL.md) ที่เป็น *ข้อมูลอ้างอิง* (สัญญา I/O, รูปแบบชุดข้อมูล, quantization)
เอกสารนี้เป็น *ลำดับขั้นที่ทำตามได้จริง* เรียงตามนี้:

| ขั้น | ทำอะไร | ได้อะไร |
|------|--------|---------|
| 1 | [เตรียมเครื่องให้เทรนได้](#ขั้นที่-1--เตรียมเครื่องให้เทรนได้) | environment ที่รันสคริปต์เทรนได้ |
| 2 | [เก็บและ label ภาพ](#ขั้นที่-2--เก็บและ-label-ภาพ) | ชุดข้อมูล Pascal VOC |
| 3 | [ตรวจชุดข้อมูล](#ขั้นที่-3--ตรวจชุดข้อมูลก่อนเทรน) | ข้อมูลที่ "เทรนได้จริง" ไม่มีข้อผิดพลาดแฝง |
| 4 | [เทรนและ export](#ขั้นที่-4--เทรนและ-export) | `traffic_light.tflite` + `labels.txt` |
| 5 | [ตรวจสัญญาและติดตั้ง](#ขั้นที่-5--ตรวจสัญญาและติดตั้งบนเครื่อง) | แอปบนเครื่องที่โหลดโมเดลใหม่ |
| 6 | [ทดสอบภาคสนาม](#ขั้นที่-6--ทดสอบภาคสนามและเกณฑ์-ใช้ได้จริง) | คำตอบว่า "ใช้ได้จริงไหม" พร้อมตัวเลข |

> **ความคาดหวังที่ถูกต้อง**: ขั้นที่ 2 (เก็บภาพ + label) ใช้เวลามากที่สุด และคุณภาพของชุดข้อมูล
> ตัดสินผลลัพธ์มากกว่าตัวโมเดล/จำนวน epoch — งานนี้เป็นงานข้อมูล ไม่ใช่แค่รันสคริปต์

## ขั้นที่ 1 — เตรียมเครื่องให้เทรนได้

แต่ละงานใช้ Python คนละช่วงเวอร์ชัน — **แยก venv ตามงาน** อย่าใช้ตัวเดียวปนกัน

| งาน | เครื่องมือ | Python ที่ใช้ได้ |
|-----|-----------|------------------|
| ตรวจชุดข้อมูล / ตรวจโมเดล / สร้างโมเดลปลอม | `validate_dataset.py`, `inspect_model.py`, `make_dummy_model.py` | 3.10 ขึ้นไป (ตัวตรวจชุดข้อมูลเป็น standard library ล้วน) |
| **เทรน + export (ทางที่แนะนำ)** | `tools/export_tflite.py` + tflite-model-maker | **3.9–3.11** และ TensorFlow ≤ 2.15 เท่านั้น |
| ทางเลือก YOLO → LiteRT | Ultralytics | 3.9–3.13 (ยังไม่รองรับ 3.14) |

เครื่องที่พัฒนาโปรเจกต์นี้ใช้ Python 3.14 + TensorFlow 2.22 ใน `.venv` —
รันงานตรวจสอบได้ครบ แต่ **เทรนด้วย `tflite-model-maker` ไม่ได้** จึงต้องสร้าง venv แยก:

```bash
# Windows (ติดตั้ง Python 3.11 จาก python.org ก่อน ถ้ายังไม่มี)
py -3.11 -m venv .venv-train
.venv-train\Scripts\activate
pip install -r tools/requirements.txt

# macOS / Linux
python3.11 -m venv .venv-train
source .venv-train/bin/activate
pip install -r tools/requirements.txt
```

`.venv-train/` ถูก `.gitignore` ไว้แล้ว (เหมือน `.venv/`) — ไม่ต้องกลัวว่ามันจะติดเข้า git

- ดาวน์โหลดแพ็กเกจค่อนข้างใหญ่ (~500 MB) และใช้เวลาติดตั้งหลายนาที
- **ไม่ต้องมี GPU** — เทรนบน CPU ได้ แต่ช้ากว่ามาก (หลักชั่วโมงขึ้นไปเมื่อชุดข้อมูลหลักพันภาพ)
- ถ้ามี NVIDIA GPU ให้ติดตั้ง `tensorflow[and-cuda]==2.15.1` ที่ตรงกับ CUDA ในเครื่องแทน ตามคู่มือ TensorFlow

## ขั้นที่ 2 — เก็บและ label ภาพ

เป้าหมายของขั้นนี้: ได้โฟลเดอร์ `dataset/` ตามรูปแบบ Pascal VOC ที่ `tools/export_tflite.py` ใช้
(โครงสร้างโฟลเดอร์และกติกาชื่อไฟล์ดู [MODEL.md §3](MODEL.md#3-ชุดข้อมูล))

### ต้องมีกี่ภาพ

| ระดับ | กล่องต่อคลาส | เหมาะกับ |
|-------|---------------|----------|
| ทดลอง pipeline | ~100 | พอให้เห็นว่าโมเดลเรียนได้ — validator เตือนต่ำกว่านี้ |
| ใช้ส่วนตัวกลางวัน | 300–500 | เริ่มพอใช้กับเส้นทางที่ใช้ประจำ |
| อยากได้แน่นขึ้น/กลางคืน | 800+ | เพิ่มภาพสภาพแสงและมุมที่หลากหลาย |

**ความหลากหลายสำคัญกว่าจำนวน**: 200 ภาพที่ต่างวัน/ต่างเส้นทาง/ต่างแสง ดีกว่า 1,000 ภาพจากวิดีโอเดียว

### เครื่องมือ label

| เครื่องมือ | หมายเหตุ |
|------------|----------|
| [labelImg] | เบาสุด, เลือก format เป็น **Pascal VOC** ได้ตรง ๆ (`pip install labelImg`) |
| [CVAT] | ใช้กับทีม, export เป็น Pascal VOC XML |
| [Roboflow] | label บนเว็บ, export Pascal VOC — ระวังเงื่อนไขการใช้งาน/ความเป็นส่วนตัวของภาพ |

[labelImg]: https://github.com/HumanSignal/labelImg
[CVAT]: https://github.com/cvat-ai/cvat
[Roboflow]: https://roboflow.com

### กฎการตีกรอบ (สั้น ๆ แต่มีผลมาก)

1. **ตีกรอบที่ดวงไฟที่ติดสว่าง** ไม่ใช่ตัวเรือนทั้งอัน — คลาสคือ *สีของไฟ* ถ้าตีทั้งเรือนจะได้ 3 ดวงในกรอบเดียว
2. **ไฟดวงเดียว = กล่องเดียว** ถ้าไฟ 1 ดวงเล็กมาก ๆ อย่าฝืนตีกรอบที่เล็กกว่า ~8 px — ปล่อยภาพนั้นไว้เป็นตัวอย่าง "ไม่มีไฟ" แทน
3. **คลาสตามสีที่ติดจริง** — ภาพที่ไฟแดงติด ให้ตี `red_light` แม้เรือนจะสีเหลือง
4. **สิ่งที่ "ไม่ใช่ไฟจราจร" ห้ามตีกล่อง** — ไฟท้ายรถ/ไฟเบรกสีแดง, ไฟสะท้อนบนกระจก, ป้าย LED สีเขียว,
   ไฟถนน, ไฟแฟลชทางข้าม: ปล่อยภาพไว้เป็น *hard negative* (ไม่มีกล่อง) ซึ่งช่วยลดการเตือนผิดได้มาก

เคล็ดลับการ label เพิ่มเติม (มุมกล้อง, ระยะ, แสง, ความสมดุลคลาส): [MODEL.md §3](MODEL.md#3-ชุดข้อมูล)

### แบ่ง train / validation

- สัดส่วน ~80% / 20%
- **แยกตามวัน/เส้นทาง/กล้อง** อย่าให้ภาพจากวิดีโอหรือช่วงเวลาต่อเนื่องกันถูกแบ่งคนละชุด
  ไม่งั้น validation จะ "โกง" ตัวเอง (เห็นภาพคล้ายภาพเทรน) แล้ว mAP สูงเกินจริง
- ภาพ hard negative ให้มีทั้งชุด train และ validation

```bash
# ตัวอย่างการสร้างโฟลเดอร์รอไว้ก่อน label
mkdir -p dataset/train/images dataset/train/annotations
mkdir -p dataset/validation/images dataset/validation/annotations
```

> ไฟล์ภาพชื่อ `001.jpg` ต้องมี annotation ชื่อ `001.xml` คู่กันเสมอ — ขั้นที่ 3 จะจับคู่ให้อัตโนมัติ
> **อย่า commit ชุดข้อมูลภาพส่วนตัวขึ้น repo สาธารณะ** (`dataset/` ถูก gitignore ไว้แล้ว) เพราะอาจมีป้ายทะเบียน/ผู้คนติดอยู่

## ขั้นที่ 3 — ตรวจชุดข้อมูลก่อนเทรน

```bash
python tools/validate_dataset.py --dataset dataset
```

ตัวตรวจจะไล่ทุกคู่ภาพ/annotation แล้วรายงานสิ่งที่ TensorFlow **ไม่ฟ้องตอนเทรน** แต่ทำให้โมเดล
"เงียบ" ไม่ตรวจอะไรเลย หรือแยกสีผิด เป็นต้น

ตัวอย่างผลลัพธ์ (ข้อมูลมีปัญหา — จะ exit 1):

```text
Dataset: dataset

train
  images: 3  annotations: 2  objects: 3
    red_light          1
    yellow_light       0
    green_light        1
    stop_sign          1   <- not a class the app knows
  warnings:
    - train has no 'yellow_light' objects; the model cannot learn that class
  problems:
    - train/images/003 has no matching annotation
    - dataset/train/annotations/001.xml: red_light: box (600.0, 450.0, 700.0, 520.0) is outside the declared image 640x480
    - dataset/train/annotations/002.xml: unknown class 'stop_sign' (expected one of red_light, yellow_light, green_light)

3 problem(s), 4 warning(s)
Fix the problems above before training -- they are what make a model miss lights.
```

ตัวอย่างตอนผ่านแล้ว (จะ exit 0):

```text
0 problem(s), 2 warning(s)
Dataset looks usable. Next: docs/TRAINING.md step 4 (train + export).
```

| ที่เจอ | ความหมาย | แก้ยังไง |
|--------|----------|----------|
| `has no matching annotation` / `has no matching image` | ภาพกับ `.xml` ไม่ครบคู่ หรือชื่อไม่ตรงกัน | เปลี่ยนชื่อให้ stem ตรงกัน (`001.jpg` ↔ `001.xml`) |
| `cannot parse XML` | ไฟล์เสีย/ถูกตัดกลาง | เปิดใน labelImg แล้ว save ใหม่ |
| `unknown class '...'` | ชื่อคลาสไม่ตรงกับที่แอปรู้จัก | แก้ `<name>` ใน XML หรือใช้ `labels.txt` ให้ตรง (โมเดลที่เพิ่มคลาสอื่น แอปจะเพิกเฉยคลาสนั้น) |
| `box has no area` | กรอบกลับด้าน/กว้างหรือสูงเป็นศูนย์ | แก้กรอบใน labelImg |
| `outside the declared image` | `<size>` ไม่ตรงกับภาพจริง หรือกรอบเกินขอบ | แก้ `<size>` ให้ตรง หรือขยับกรอบเข้ามา |
| `has no images` | โฟลเดอร์ผิด/นามสกุลไม่รองรับ | ใช้ `.jpg`/`.jpeg`/`.png`/`.bmp` |
| warning `no 'yellow_light' objects` | คลาสนั้นไม่มีเลย → โมเดลเรียนไม่ได้ | เก็บภาพคลาสนั้นเพิ่ม |
| warning `only N ...` / `is X% of the largest class` | ข้อมูลไม่สมดุล → bias ไปคลาสที่เยอะ (ไฟเขียวมักเยอะสุดจากถนนจริง) | เก็บคลาสน้อยเพิ่ม หรือ oversample และตรวจอีกรอบ |

Exit code: `0` = ใช้ได้, `1` = มีปัญหา (แก้ก่อน), `2` = ใช้คำสั่งผิด

> `tools/export_tflite.py` เรียกการตรวจชุดเดียวกันนี้ให้เองก่อนเริ่มเทรน — เจอปัญหาเมื่อไรจะหยุดทันที
> พร้อมบอกว่าต้องแก้ไฟล์ไหน (ไม่ต้องรอ TensorFlow เริ่มทำงาน)

## ขั้นที่ 4 — เทรนและ export

### ทางที่ 1 (แนะนำ) — `tools/export_tflite.py` ในโปรเจกต์

ทำที่ขั้น 3 ให้ผ่านก่อน แล้วรันใน venv ที่เตรียมไว้ (ขั้นที่ 1):

```bash
python tools/export_tflite.py \
  --dataset dataset \
  --model efficientdet-lite0 \
  --epochs 50 \
  --output app/src/main/assets
```

สคริปต์จะ: ตรวจชุดข้อมูล → เทรน → ประเมินบน validation → เขียนสองไฟล์นี้ทับของเดิม

- `app/src/main/assets/traffic_light.tflite` — โมเดล
- `app/src/main/assets/labels.txt` — เขียนจาก `CLASS_NAMES` ในสคริปต์ (ลำดับ `red_light`, `yellow_light`, `green_light`)

| ตัวเลือก | ค่าเริ่มต้น | เลือกเมื่อ |
|----------|------------|------------|
| `--model` | `efficientdet-lite0` | `lite1`/`lite2` เมื่อไฟระยะไกลพลาดบ่อยและยอมให้ช้าลง |
| `--epochs` | 50 | ลดเมื่ออยากลองเร็ว ๆ; เพิ่มถ้า loss ยังลงอยู่ |
| `--batch-size` | 8 | ลดเป็น 4 ถ้า RAM/VRAM ไม่พอ (`OutOfMemoryError`) |
| `--output` | `app/src/main/assets` | — |
| `--tflite-filename` | `traffic_light.tflite` | ตั้งชื่ออื่นเมื่ออยากเก็บหลายเวอร์ชัน |

**อ่านผลประเมิน**: ตอนจบสคริปต์พิมพ์ `model.evaluate(validation)` ออกมา (mAP ต่าง ๆ)
ใช้เป็น *แนวโน้ม* ไม่ใช่คำตัดสินสุดท้าย — ดูตารางเกณฑ์จริงในขั้นที่ 6

| mAP (validation) | ตีความ |
|------------------|--------|
| < 0.3 | ยังไม่ควรออกถนน — กลับไปขั้นที่ 2/3 (ข้อมูลน้อย/ไม่สมดุล/กรอบไม่ดี) |
| 0.3–0.5 | พอใช้กลางวันบนเส้นทางที่คล้ายภาพเทรน |
| > 0.5 | เริ่มนิ่ง — ไปทดสอบภาคสนามได้ แต่ยังต้องทดสอบจริงเสมอ |

### ทางที่ 2 — YOLO → LiteRT (สำหรับ Python ใหม่กว่า 3.11)

ถ้าไม่อยากสร้าง venv 3.11: เทรน YOLO แล้ว export เป็น TFLite **ที่มี NMS อยู่ในกราฟ** (`nms=True`)
รูปแบบ output จะตรงกับสัญญาของแอป (ดู [MODEL.md §4 ทางที่ 3](MODEL.md#4-เทรนและ-export)) มุมที่ต้องระวัง:

- **ต้องมี NMS ในกราฟ** — โมเดลที่ยัง output anchor ดิบ (`[1, 8400, 85]`) ใช้กับแอปนี้ไม่ได้
- **class order ของโมเดล = index ใน `labels.txt`** — ตรวจด้วย `inspect_model.py` แล้วแก้ `labels.txt` ให้ตรงก่อนใช้
- Ultralytics ย้ายเอกสารไปหัวข้อ **LiteRT** แล้ว — ดู flag ล่าสุดของเวอร์ชันที่ติดตั้ง

### ทางที่ 3 — TensorFlow Model Garden / Keras

เทรนเองได้ทั้งหมด ขอแค่ตอน export ให้ได้ output 4 tensor ตามสัญญา (locations `[1, N, 4]`,
classes, scores, num_detections) และใช้ INT8 converter snippet ใน [MODEL.md §4 ทางที่ 2](MODEL.md#4-เทรนและ-export)

> **INT8**: โมเดล INT8 เล็กและเร็วขึ้นหลายเท่าบน CPU เหมาะกับใช้งานจริงมาก แต่ถ้าต้องการ GPU delegate
> ให้ใช้ float32 — แอปรองรับทั้งสองแบบโดยไม่ต้องแก้โค้ด (ดู [MODEL.md §5](MODEL.md#5-quantization))

หลัง export เสร็จ **อย่าลืมตรวจสัญญาก่อน** (ขั้นที่ 5) — โมเดลที่เทรนเสร็จแต่ output ไม่ตรง
จะโหลดไม่ขึ้นหรือตรวจจับไม่ได้เลย

### ทดสอบแบบ static ก่อนออกถนน (สำคัญ)

1. เปิดภาพไฟจราจรบนจอคอมพิวเตอร์ (หรือพิมพ์ใส่กระดาษ) ให้ **ไฟดวงเดียวเด่น ๆ ชัด ๆ**
2. ชี้กล้องไปที่ภาพ ดูว่ามีกรอบขึ้นและสีที่ทำนายถูก
3. ลองทั้ง 3 สี (แดง/เหลือง/เขียว) และลองขยับระยะ

ถ้าขั้นนี้ไม่ขึ้นกรอบ — โมเดลมีปัญหาที่ข้อมูล/scaling ไม่ใช่ "ถนนจริงยาก" ให้ไล่ตาม
[TROUBLESHOOTING §ตรวจจับไม่เจอ](TROUBLESHOOTING.md) ก่อน

> อย่าลืมว่าถ้าติดตั้ง APK เก่าอยู่บนเครื่อง โมเดลในนั้นคือชุดเดิม — build/install ใหม่ทุกครั้งหลังเปลี่ยน `.tflite`

## ขั้นที่ 6 — ทดสอบภาคสนามและเกณฑ์ "ใช้ได้จริง"

> ⚠️ **ความปลอดภัยก่อน**: แอปนี้เป็นตัวอย่างเพื่อการเรียนรู้ ไม่มี fail-safe
> ห้ามให้คนขับถือ/มองจอ — ให้ผู้โดยสารเป็นคนเฝ้า หรือจอดรถทดสอบตอนปลอดภัย

วิธีทดสอบที่ให้ข้อมูลจริง (ไม่ใช่ "รู้สึกว่าโอเค"):

1. เลือก 2–3 ทางแยกที่คุณใช้จริง (ไม่ใช่แยกที่ถ่ายภาพมาอย่างเดียว)
2. เริ่มจากกลางวัน แล้วข้ามทางแยก ~10 รอบ — ทางไหนก็ได้ แต่มองได้ทั้งไฟและจอ
3. ทุกรอบ จด 4 อย่าง: **(ก)** ตรวจเจอไฟไหม **(ข)** สีถูกไหม **(ค)** เตือนไฟเขียวตรงจังหวะไหม **(ง)** เตือนผิดไหม
4. ทำซ้ำกลางคืน/ฝน ถ้าคุณต้องใช้ในสภาพนั้น
5. ใส่ผลลงตารางที่ภาคผนวก ก

### เกณฑ์ผ่านแนะนำ (ปรับได้ตามเส้นทางของคุณ)

| ตัวชี้วัด | เป้าหมายเริ่มต้น | ถ้าไม่ผ่าน |
|----------|------------------|-------------|
| ตรวจเจอไฟเขียวที่ระยะ 20–30 ม. (กลางวัน, ตรง) | ≥ 80% ของจังหวะไฟ | เก็บภาพระยะไกลเพิ่ม หรือเปลี่ยนเป็น lite1/lite2 |
| เตือนไฟเขียว | ภายใน ~1 วินาทีหลังเข้าเกณฑ์ | ถ้าดังช้า/ไม่ดัง: ดูสไลเดอร์ threshold, gate (3 เฟรมติดกัน) ใน [CONFIGURATION.md](CONFIGURATION.md) |
| เตือนผิด (ไม่มีไฟเขียวตรงหน้าแต่ดัง) | ≤ 1 ครั้ง / 10 นาที | เพิ่ม threshold, เก็บ hard negatives เพิ่ม (ขั้นที่ 2) |
| FPS | ≥ 8 | ดู [TROUBLESHOOTING §กล้องและประสิทธิภาพ](TROUBLESHOOTING.md) |

**ทำไมไม่ดู mAP อย่างเดียว**: mAP วัดบน validation ที่เราจัดมา แต่มือถือติดในรถเจอต่างออกไป —
แสงกลางแจ้ง, สะท้อนกระจก, มุมเงย, ระยะไกล, ภาพสั่น เกณฑ์ในตารางนี้จึงเป็นการวัดจาก "ถนนจริง" ของคุณ

## แก้ปัญหาเมื่อโมเดลยังไม่ดี

| อาการ | สาเหตุที่พบบ่อย | ทางแก้ |
|-------|-----------------|--------|
| ไม่มีกรอบขึ้นเลย แม้ทดสอบ static | label map ไม่ตรงกับ index โมเดล, input scaling ผิด, โมเดลเสีย | ตรวจ `labels.txt` + `inspect_model.py`; scaling: [MODEL.md §1](MODEL.md#ค่า-input-scaling) |
| กรอบขึ้น แต่ทายสีผิดบ่อย | กรอบตอน label คลุมทั้งเรือน/หลายดวง | ตีกรอบเฉพาะดวงไฟที่ติด, เพิ่มภาพคลาสที่ทายผิด |
| พลาดไฟแดง/เหลือง (พบยากอยู่แล้ว) | คลาสนั้นมีข้อมูลน้อย (ดู warning ของ validator) | เก็บไฟแดง/เหลืองเพิ่ม, oversample, ตรวจสัดส่วนคลาสอีกรอบ |
| เตือนผิดตอนไม่มีไฟเขียว | ไฟเขียวจากเลนอื่นในภาพ, สะท้อน/ป้าย LED, threshold ต่ำ | เก็บภาพเหล่านั้นเป็น hard negative, เพิ่ม threshold, เพิ่มจำนวนเฟรมยืนยัน |
| ไฟระยะไกลพลาด | ไฟกินพื้นที่ไม่กี่พิกเซล | lite1/lite2, เพิ่มภาพระยะไกล, หลีกเลี่ยงการย่อภาพเพิ่มก่อนเข้าโมเดล |
| ช้า เครื่องร้อน | float32 + โมเดลใหญ่ + ความละเอียดสูง | INT8, lite0, เพิ่ม `minIntervalMillis` ([CONFIGURATION.md](CONFIGURATION.md)) |
| กลางคืนแย่กว่ากลางวันมาก | ภาพกลางคืนในชุดเทรนน้อย | เก็บภาพกลางคืนเพิ่ม; การชดเชยแสง (gamma/CLAHE) ยังไม่มี — ดู [ROADMAP.md](ROADMAP.md) |

## วนปรับให้ดีขึ้น (ทำซ้ำแบบมีทิศทาง)

1. **เก็บ "เฟรมที่พลาด"** จากขั้นที่ 6 (screenshot หรือถ่ายรูปหน้าจอ/ฉากนั้นไว้)
2. เพิ่มภาพนั้นเข้า `dataset/` — ผิดเพราะไม่มีกล่อง → ทำเป็น hard negative; ผิดเพราะกล่อง/สี → ตีใหม่
3. รัน `python tools/validate_dataset.py --dataset dataset` ให้ผ่าน
4. เทรนใหม่ (parameter เดิมก่อน เพื่อเทียบกันได้) แล้วตรวจด้วย `inspect_model.py`
5. เทียบผลด้วยตัวเลขเกณฑ์เดิมจากขั้นที่ 6 — **เก็บเฉพาะโมเดลที่ตัวเลขดีกว่า** และจดไว้ใน commit message
   ว่าเวอร์ชันนี้แก้จากเวอร์ชันก่อนตรงไหน
